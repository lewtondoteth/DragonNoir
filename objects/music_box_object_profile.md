# Music Box Object Profile

Working object profile for the opening-case music box.

This file preserves what the object currently is in the story, what it appears to be, and what should remain undefined.

Use alongside:

- `../cases/opening_music_box_case_profile.md`
- `../notes/opening_case_music_box_scaffold.md`

---

# 1. Current Status

The music box is an active working object with stable outward logic and intentionally unstable deeper meaning.

Stable:

- it is the target object of the opening case
- it was stolen as part of a larger haul
- it matters beyond ordinary treasure value

Undefined:

- its larger purpose
- its final mechanical, symbolic, or operational role

---

# 2. Surface Identity

Outwardly, the music box should read as:

- valuable
- old
- portable
- mechanically intricate
- emotionally resonant
- plausible dragon treasure
- ordinary enough to be catalogued among other valuables
- functional or described as working, so its mechanism has living toy-world weight
- marked by age or history, such as a faded or partial maker's mark, without immediately explaining what that history means

It should make immediate sense that Dragon would recognize it as treasure even before understanding why it matters more than the rest of the haul.

---

# 3. Social Readings

Different parties should read the music box differently:

- Dragon: precious treasure, emotionally or species-level significant
- Odette: treasure cover story plus concealed real importance
- owner: valuable object worthy of recovery and reward
- thief: part of a professional haul, not necessarily the true centerpiece
- commissioning party: the object that actually matters
- police: stolen property among other missing valuables

This layered reading is part of what makes the case work.

---

# 4. Investigative Function

The object should support:

- noir treasure logic
- hidden-stakes escalation
- clue trails the police may misread or miss
- conflict between public property logic and private hidden purpose

The object is not yet fixed as:

- a key
- a device
- a memory container
- a ritual component
- a mechanism with named mythology

Any of those may become true later, but they are not yet canon.

---

# 5. Writing Constraints

Preserve:

- treasure readability
- concealed deeper significance
- enough ordinary value to fit inside a broader burglary
- sparse public description that makes the object look ordinary to outsiders
- private pressure around the object that Odette and Dragon register before the reader knows why

Avoid:

- explaining the real purpose too early
- making the object's importance read as obvious to every party
- hard-fixing mythology or mechanism before the story earns it
